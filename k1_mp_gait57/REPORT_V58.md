# v5.8 実験: 足首ロールを全区間で受動バネダンパ化（歩行・旋回・走行）

- 作成日: 2026-11-19 / ブランチ: `exp/v58-ankle-roll-spring`（main は無変更）
- 条件: 足首ロールの受動バネ K=10 Nm/rad、減衰 D=0.6 Nm·s/rad（`K1_ANKROLL_SPRING=10 K1_ANKROLL_DAMP=0.6 W_WALK_M=0.11`）
- 検証環境: MuJoCo 4.0.1 / torch 2.15 CPU（2コア）。v5.6.3 の数値も同じ環境で再測している
- 採用ポリシー: `runs/final58/walk.pt`（exp59a 200回時点）＋ `runs/final58/run.pt`（r58a 300回時点）

## 1. exp58c からの修正点

1. **走行環境にバネが入っていなかった不具合を修正**（`k1env_run.py`）。`K1RunBatch` がモデルを作り直す際に、`K1EcoBatch` で入れたバネが消えていた。修正前の exp58c は、走行区間を足首モーターのまま評価していた。走行区間にもバネを入れると、旧走行ポリシーではコース生存率 0.25（4.5 m/s で旋回中に転倒）。
2. **走行ポリシーをバネ前提で再学習**（r58a）。
3. **歩行・旋回ポリシーを省エネ寄りに再学習**（exp59a、exp58c から開始）。
4. **電力は J/m（実速度で割った値）で比較する**。`diag.py` に実速度 `v_meas` と `J_per_m` を追加した。W の値だけでは、遅く歩くほど安く見えてしまう（後述）。

## 3. 評価

- 姿勢: ロール RMS は v5.6.3 の 2.97° に対して 1.41°（約半分）。exp58c（0.66°）よりは揺れる。
- 省エネ: J/m では exp58c より −6%、v5.6.3 より **+12%**。**v5.6.3 と同等という目標は未達**。
- 速度追従: 1.0 m/s 指令に対して 0.87 m/s（v5.6.3 は 0.96）。exp57 系列から引き継いだ遅れがある。
- 外乱耐性: 駆動版より弱い。

## 4. うまくいかなかった試み（記録）

| 試み | 結果 |
|---|---|
| exp59a を 600 回まで延長 | W は 125.6 W まで下がったが、実速度が 0.77 m/s に落ちて J/m 164（悪化） |
| exp59b（外乱の頻度を倍にして +300 回） | 108.6 W・0.68 m/s・J/m 160。外乱耐性は改善しなかった |
| exp59c（速度報酬 kv 40→80、電力価格を少し戻して +300 回） | 0.83 m/s・J/m 152。速度は戻らなかった |

教訓: 電力の価格を上げると、方策は「遅く歩く」抜け道を選ぶ。次の手は報酬の重みではなく、構造で塞ぐこと。たとえば (a) 報酬を W ではなく J/m（電力 ÷ max(v, v_ref)）で価格付けする、(b) 速度が足りないときに電力報酬をゼロにするゲートを入れる。

# v5.8b 追加学習: 速度追従を戻しつつ、exp58c 並みの姿勢と電力抑制（exp60a → exp60b）

採用: `runs/final60/walk.pt`（exp60b 100回時点）＋ `runs/final60/run.pt`（= final58 の走行ポリシー）

## 変更（`k1env_walk3.py`、`E_PER_M=1` のときだけ有効。既定は従来どおり）
- **電力を距離あたりで価格付け**: 電力の罰則 × clip(v_ref / v_ema, 1, 2.5)。v_ema は約1秒の移動平均速度。遅く歩くほど 1 W あたりが割高になる（速く歩いても割引はしない）
- **速度不足の罰則**: `VDEF_W` × max(v_ref − v_ema − 0.03, 0)
- 姿勢の設定は exp58c（train_env5）に戻した。設定ファイルは `training/train_env9.sh`（exp60a）と `train_env10.sh`（exp60b、`HIPCU_W=0.006`）

```bash
source training/train_env9.sh   # exp60a: exp58c から 400 回、kv_walk 60、w_energy 0.002
python3 ppo_walk4.py --iters 400 --init runs/init/exp58c_model.pt --sym 1.0 --lr 3e-5 --lr_min 2e-5 --kv_walk 60 --w_energy 0.002 --out runs/exp60a
source training/train_env10.sh  # exp60b: exp60a から 400 回、w_energy 0.0035
python3 ppo_walk4.py --iters 400 --init runs/exp60a/model.pt --sym 1.0 --lr 3e-5 --lr_min 2e-5 --kv_walk 60 --w_energy 0.0035 --out runs/exp60b
```

## 所見
- 速度は戻った（0.87 → 1.00 m/s）。距離あたりの価格付けで「遅く歩く」抜け道が塞がった
- 姿勢を exp58c 並み（0.7°台）に保つと、J/m は 156〜159 で頭打ちになる。
  原因は股関節ロール銅損（54〜60 W）。足首で横バランスを取れない分を股関節が担っており、「垂直姿勢」と「省エネ」が物理的にぶつかっている
- 外乱への耐性は弱いまま
- 次の候補: (1) バネ剛性 K を上げる（K=40 で股関節銅損が約 −2 W という前回のスイープ結果あり）、または中立角の可変化。(2) ロール許容幅をごく小さく（〜1°）残す。(3) 外乱付きの立ち・歩き出しを重点的に学習する
